# テストプレイ AI（パッケージ版をひたすら遊ぶ強化学習の AI）

パッケージ化したゲーム（`Packaged/Windows/KakurenboIncremental.exe`）を、外から文字だけで遊ぶ AI。
**一度作った後は Claude を使わない**（AI は手元の Python。学習・報告書づくりもこのパソコンの中だけで行う）。

## 使い方

```
Tools\AgentPlaytest.bat
```

- ダブルクリックで、5 つの性格を同時に **8 時間**遊ばせ、終わったら報告書をブラウザで開く
- **8 時間が終わって 5 分キーボード・マウスにさわらなければ、同じデータのまま続けてもう 8 時間遊ぶ**（何回でも。さわると終わって報告書を開く）。
  学習・ゲームのセーブ・記録のフォルダはそのまま続き。`-NoRepeat` で 1 回で終わる・`-IdleMinutes 10` で待つ時間を変える
- 時間などを変えるとき（PowerShell）：
  - `powershell -ExecutionPolicy Bypass -File Tools\AgentPlaytest.ps1 -Hours 2`（2 時間）・`-Until 07:30`（その時刻まで）
  - `-Personas near`（1 つだけ。`stay` / 
ear` / `greedy` をカンマで）
  - `-Fresh`（ゲームのセーブと学習を消して、はじめから。**最初の 1 回は付けると「はじめからクリアまで何分」が測れる**）
- **リセットのツール**：`Tools\ResetAgentPlaytest.bat`（ダブルクリック）／`Tools\ResetAgentPlaytest.ps1`。学習（`brains/`）・ゲームのセーブ（`Agent*.sav`）・記録のフォルダ（`<起動日時>/`）・バランスの推論（`analysis/`）を、
  一覧を見せて確かめてから `Saved/AgentPlaytest/backup_<日時>/` へ移す（消さない。元に戻すときは中身を元の場所へ）。遊んでいる最中は何もしない。
  `-Personas greedy`（その性格の学習とセーブだけ）・`-KeepRecords`（記録と推論は残す）・`-NoBackup`（移さずに消す）・`-Yes`（確かめない）・`-DryRun`（見せるだけ）。
  あなたのセーブ・設定・GitHub の報告書には触れない
  - `-Speed 1`（人と同じ速さ。既定は 2：ゲームの時間を 2 倍にして、1 時間で 2 時間ぶん学ぶ）
  - **既定で軽くして動かす**：ゲームのコマ数に上限（ゲームの速さ × 20。速さ 2 なら 40）・画質を一番低く・描く解像度を半分・
    ゲームと AI の優先度を「通常以下」（ほかの作業を先に動かす）。AI は画面の絵を見ないので、判断は変わらない。
    `-Full` で軽くしない・`-MaxFPS 40` で上限を変える（既定 30。5 つ同時で PC 全体の CPU が約 7 割）（まだ重いときは `-Personas near` のように数を減らす）。
    測った値（12 コアのパソコン・1 つのゲーム）：ふつう CPU 全体の 33% → 軽くすると 9.6%（3 つ同時で約 100% → 約 30%）
  - `-Watch`（ウィンドウを大きく）・`-Sound`（音を出す）・`-Open`（終わったら報告書を開く。bat は付けている）
  - `-NoPublish`（報告書を GitHub へ送らない。下の「外出先で見る」）
- 先にパッケージ化しておく（`Tools\AutoBuild.bat`。C++ を変えたらパッケージも作り直す）
- 必要なもの：Python 3.8 以上（標準ライブラリだけ。`python`・`py`・uv の Python を自動で探す）
- ゲームのセーブは専用のスロット（`Agent_stay` など）。**あなたのセーブ・設定は読み書きしない**
- 遊んでいる間、ゲームのウィンドウは本物のマウス・キーボードを受け付けない（AI だけが操作する）
- 遊んでいる間はパソコンがスリープしない（Windows の電源の設定は変えず、終わったら元に戻る。ふたを閉じる・手動でスリープにしたときは止まる）

### 記録と報告書

`KakurenboIncremental/Saved/AgentPlaytest/<始めた日時>/`（起動するたびに新しいフォルダ。学習とゲームのセーブは前回の続き。`-Continue` で前回のフォルダに書き足す）

| ファイル | 中身 |
|---|---|
| `report.html` | 報告書（グラフ付き。15 分ごとと最後に作り直す） |
| `report_2周目.html`・`report_2周目.md`… | 続けて遊んだ 2 周目からの報告書（周の番号付き。中身はフォルダの最初からの記録。1 周目の report.html はそのまま残る） |
| `report.md` | 同じ内容の Markdown |
| `<性格>/report.md` | 性格ごとの報告 |
| `<性格>/rounds.jsonl` | 1 ラウンド 1 行（ステージ・館・鬼・逃げ切ったか・隠れた秒数・拠点・囲い方・行動の回数・見つけた鬼…） |
| `<性格>/events.jsonl` | お店で買った物・設置・転生・初めて読んだ鬼の紹介・ステージ到達・起動 |
| `<性格>/bugs.jsonl`・`bug_counts.json` | 見つけたおかしなこと（同じものは 1 行。回数は別のファイル） |
| `<性格>/crashes.jsonl` | ゲームが落ちた・固まった（ログの最後のエラーの行） |
| `<性格>/shots/` | 不具合を見つけたとき・設置のときのスクリーンショット |
| `<性格>/game_NN.log` | ゲームのログ（起動ごと） |

学習（続けて遊ぶと上達し続ける）：`KakurenboIncremental/Saved/AgentPlaytest/brains/brain_<性格>.json`。
報告書だけ作り直すとき：`python Tools/AgentPlaytest/make_report.py <記録のフォルダ>`

### 外出先で見る

- **報告書**：起動スクリプトが 15 分ごとと最後に、GitHub のブランチ `agent-reports` へ送る（Claude は使わない）。
  **PC の名前のフォルダの同じファイルを上書きする**（新しく作らない。前の版は Git の履歴に残る）：https://github.com/taiyakinosippo/KakurenboIncremental/tree/agent-reports/KIC-GAME-A-25 （このパソコン。フォルダを開くと `README.md`＝報告書がそのまま出る。スマホの GitHub アプリでも表のまま読める。`<性格>.md` に性格ごとの報告、`report.html` はグラフ付き）。ほかの PC で動かしても混ざらない。
  **走りごとのフォルダ** `<PC の名前>/<起動日時>/`（例 `KIC-GAME-A-25/20261016-0914/`）にも、その走りの報告書（`README.md`・`report.html`・`<性格>.md`）を 15 分ごとに送り
  （続けて遊んだ 2 周目からはその下の `<n>周目/`（例 `20261016-0914/2周目/`）に同じ形で。記録はフォルダの最初からの分）、
  1 周の終わり（と Ctrl+C で止めたとき）に走りの記録 `data/`（`launcher.log`・`run.json`・性格ごとの `rounds.jsonl.gz`・`events.jsonl.gz`・`bugs.jsonl.gz`・`crashes.jsonl.gz`・`bug_counts.json`。.jsonl は gzip）を送る。前の走りのフォルダは消さない
- 記録は**始めた日時のフォルダ**に書く（`-Continue` で前回のフォルダの続き）。GitHub の報告書は今の周の物で同じファイルを上書きする
  手元の main・作業中のファイルには触れない（一時的なインデックスでコミットを作り、そのブランチへ push するだけ。ほかのパソコンの pull・自動ビルドにも影響しない）
- **Claude とのチャット**：Claude Code のセッションの「Remote Control」をオンにすると、claude.ai/code やスマホのアプリから続きを見て指示できる

## 5 つの性格

| 性格 | 隠れ場所に着いてから | 得点のおまけ | 転生のお店の優先度（左が先） |
|---|---|---|---|
| `stay` 慎重型（その場から動かない） | 一歩も動かない。連打するか、静かにしゃがむか（道具は使う） | なし | よじ登る → 壁の硬さ → お金アップ（連打・時間） |
| 
ear` 慎重型（近くのお宝だけ取る） | 拠点から 8 マス以内のお宝だけ取りに行く。追われたら逃げる・煙幕 | お宝 1 個 +1 | 煙幕（ダッシュ・数） → よじ登る → お宝の宝石 → 壁の硬さ |
| `greedy` 強欲型（お宝をほぼ全部取る） | 見えた・音で見当をつけたお宝は全部取りに行く。無ければ歩いていない所を探す | お宝 1 個 +3 | 煙幕（ダッシュ・数） → お宝の宝石 → 連打のお金アップ |
| `builder` 建築大好き（壁と罠で足止め） | 動かない（stay と同じ）。壁・壁の補強・罠を優先して買い、1 段高く積み、罠は全部置く。囲わない型は使わない | なし | よじ登る → 壁の硬さ → 時間のお金アップ |
| `nowall` 壁なし（ダッシュで逃げる） | 壁を一切置かない・買わない（壁の補強も）。罠と宝石の道具は使う。近くのお宝は取りに行き、追われたら逃げる・煙幕 | お宝 1 個 +1 | 煙幕ダッシュ → 煙幕の数 → お宝の宝石 |

ラウンドの流れ（どの性格も。ユーザーの指定）：

1. 設置パートで、館全体（上から見た見取り図）を見渡して隠れやすい場所を探し、そこを壁で囲む（出入り口を 1 つ残す）
2. **スタートは、初めての館はマップの中央**（歩いて見渡し、隠れ場所を見つける）。**隠れ場所までたどり着けたことのある館は、隠れ場所のそば**（brain の `start_spots`。置けなければ中央）。「もういいかい」の間から歩き出す
3. **隠れ場所に着くまでは、お宝を優先して取りつつ、鬼の足音から遠ざかる**：見えた・覚えている・音で見当をつけたお宝に寄り道する
   （ただし鬼が 5 マス以内・鬼の足音が 10 マス以内・お宝のそばに鬼がいそう・始まって 8 秒は鬼の門のまわり、は寄らない）。
   鬼が 7 マス以内・追われたら離れる。隠れ場所が鬼の近くなら、見渡したときの別の候補に変える。制限時間の 4 割たったら、その場から性格ごとの隠れ方へ
4. 隠れ場所に着いたら、性格ごとの隠れ方（Q 学習）

転生のお店は優先度の言葉（「よじ登る」「硬さ」「煙幕」「お宝」「お金アップ」）を商品の名前に当てはめ、今のポイントで買える一番左の物を買う。
優先度の物がまだ高くて買えないときはポイントをためる。

### 勝ちやすい物を優先（コインのお店・宝石のお店）

- 買った物ごとに「そのラウンドで逃げ切ったか − そのステージのふだんの逃げ切りの割合」（勝率の上がり幅）を記録する（`brain.item_wins`・`stage_clear`）
- 6 回以上試した物は、上がり幅 × 1.5 を商品の良さに足す（勝率 +20% なら +0.3。勝ちやすい物を見つけたらそれを優先して買う）
- **お金の強化（連打・時間のお金・ゴールドラッシュ）は今回と次回のラウンドの上がり幅を足して**評価する（稼いだお金は次のラウンドの買い物で効くため）
- 慎重型・強欲型（stay / near / greedy）は壁を気持ち多めに置く（`wall_lean`：囲う型を少しひいき・壁の見当を上げる・壁を少し早く高く積む）。建築大好き・壁なしは変えない

### 宝石のお店の道具を試す（使った結果を知るため）

- お宝を優先して取る（上の 3）ので、宝石がたまりやすい
- 宝石のお店では、**まだ試した回数の少ない道具から**買う（同じなら安い物）。どれも 3 回ずつ使ったら、**使ったラウンドの勝ちやすさが高い物を優先**（下の「勝ちやすい物を優先」）。置く道具は設置パートで毎回置き、かくれんぼ中に使う道具（だるまさん）は、追われた・鬼が 6 マス以内に見えたら使う
- 報告書の「宝石のお店の道具を使った結果」：道具ごとに、使ったラウンドと**同じステージで使わなかったラウンド**の逃げ切り・隠れていた割合、
  本当に起きたこと（真っ暗・ゴールドラッシュ・猫をなでた鬼・人形を追った鬼・止まった鬼。窓口の本当の値）と、AI に見えた効き目
- 宝石と宝石の道具は転生するとなくなるので、周の前半に多く使う

## AI が知っていること・知らないこと（要件 1）

- **知らない**：ゲームの仕様（GameDesign.md・Data/*.csv・鬼の数値・道具の効果）。AI のコードにも書いていない
- **見えるもの（文字だけ）**：ゲームの「テキストの窓口」が送る文字
  - 画面に描いた文（お店の商品と説明・鬼のチュートリアル・ヒント・結果・左上の鬼の一覧の様子のことば）
  - 押せるボタンとその文字・画面に出ている名前（「鬼の門」「スタート」）
  - 上から見た館の形（`. 床 / 1 低い家具 / 2 背の高さくらい / 3 2 段ぶん / # 部屋の壁 / g 赤い床`）と置いた壁・道具
  - 見えている鬼・お宝（壁や家具にさえぎられていないもの）、聞こえた音（音の名前・方角・大きさ）、自分の体の様子
  - 床に広がった輪（クリックの黄色の輪・足音の輪など。場所・大きさ・色・太さだけで、意味は送らない）
  - 文字ではない目盛り（煙幕の残りの四角）は文字にして送る
- **読む力**：一般的な言葉の辞書（`reader.py`。「壁」「壊す」「足音」「敏感」「〇〇に弱い」「対策」…）。
  鬼のチュートリアルを読んで「この鬼は壁を壊す・足音に敏感」と見当をつけ、遊んだ結果（速さ・壁をこわしていた回数・見つかった回数）で上書きする。
  **自分の体でできること**（`reader.ability_tags`）：かくれんぼ中の操作の欄・ヒントに「登」があれば登れる、同じ文に「逃げ」なら追われたら段を越えて逃げる
  （逃げ先に段の向こうも入れ、`goto … climb`）、「外に出」と「戻」なら囲いを登って外のお宝を取りに行き戻る。読んだ使い方は学習（brain の `abilities`）に残る。
  「解放」と書いた文（まだ使えない物）は数えない。窓口の `goto … climb` は登れる高さ（転生のお店のよじ登る Lv3 から 2 段）の壁を少し遠い道として通り、段の手前で登る
- 窓口は記録用に本当の値（`TEL` の行：ステージ・鬼の種類と場所）も送るが、**AI の判断には使わない**（`recorder.py` だけが読む。報告書と不具合の検出用）

## 強化学習（要件 2・3）

得点 ＝ **隠れていられた割合**（隠れた秒数 ÷ 制限時間。逃げ切ると +0.5）。長く隠れられるほど高い。

| 学ぶもの | やり方 | 状態・特徴 |
|---|---|---|
| 隠れ場所（拠点） | ベイズ線形回帰＋トンプソン抽出（試しつつ良い所を選ぶ）。同じ館の同じ場所で実際どうだったかも混ぜる | 門から遠い・まわりがふさがっている・背の高い物／低い物・見通し・行き止まり・囲むのに要る壁・広さ・館のまんなか・スタート（中央）から遠い、と鬼の印との掛け合わせ |
| 囲い方の型 | 型ごとに同じく線形モデル（文脈＝そのステージの鬼の印） | 囲わない・門の反対に出入り口・二重・囲わず罠・**柱に乗る**（隠れ場所に 2 段の柱、となりに 1 段の踏み台＝階段。よじ登れて、案内の文で「鬼は 2 段の壁に飛び乗れない」と読んだときだけ。踏み台はクライミング壁（説明に「登」）を先に買って置く。床 → 踏み台 → 柱と 1 段ずつ登り、柱の上では降りて逃げない）（中央から歩いて入るので、全部閉じる型は使わない） |
| かくれんぼ中の動き（隠れ場所に着いてから） | 表形式の Q 学習（止まる行動は 0.4 秒ごと、歩く行動は着くか危なくなるまで続けるオプション） | 状態：鬼の近さ（見えた・危ない音）・追われているか・拠点からの距離・囲いが無事か・取れるお宝・煙幕・残り時間 / 行動：連打・静かにしゃがむ・逃げる・拠点へ戻る・お宝を取る・お宝を探して歩く・煙幕・道具 |
| お店の商品 | 買った後のラウンドの得点（ステージごとの基準との差）で商品ごとの良さを更新 | 商品の名前（初めての物は少し試したくなる） |
| 転生のタイミング | 多腕バンディット（同じステージで 2・4・7・12 回続けて失敗したら転生 → その周でどれだけ先へ進めたか） | |
| 音の危なさ | その音のあと 3 秒以内に鬼が 6 マス以内に見えた割合 ÷ ふだんの割合 | 音の名前の意味は知らない |
| **床の輪**（クリックの輪・足音の輪） | 輪の見た目（色・太さ）ごとに、自分の足元に出たか・そのときの自分の様子（連打・歩く・しのび足・よじ登る…）・半径を数える。輪が出たときに見えていた鬼が 3 秒以内に輪の方へ来た・追ってきた割合を、輪の中と外（距離 ÷ 半径の段ごと）でくらべ、何倍か・半径の何倍まで届くかを学ぶ | 「連打したら輪が鬼（見えた鬼・足音の見当）に届くか」を Q 学習の状態（`H0` 分からない / `H1` 届かない / `H2` 届く）に入れ、**連打するかは Q 学習が決める**（ばれるかの判断を学習中に覚える）。歩く輪が届いた鬼は気づくと分かったら、鬼に届くときはしのび足で歩く |
| **音の聞き分け**（鬼の足音・お宝の音） | 3 つの手がかりで点数を付ける：①方角（15° 刻み）にそのとき鬼・お宝（見えている・覚えている）・自分の道具があった割合が、ふだんの何倍か ②鳴る間隔（足音のように細かく続く／ときどき鳴る）③その後に鬼が来るか。大きさ → 距離も、見えていた物までの距離で学ぶ | 鬼の足音らしい音が 6 マス以内（見えた鬼が 6 マス以内）なら**連打をやめる**（学習より先に効くきまり）。お宝の音らしい音がしたら、その方角・距離にお宝があると見当をつけて取りに行く |

## 報告書に書くこと（要件 6・7）

- **今の状況**（更新した時点の何周目・今のステージ・クリアした最大ステージ（全部 / この周）・挑戦回数（全部 / 今のステージ））
- **AI が攻略で大事なことに気づいた時間**（遊んだ時間・周・ステージ・何ラウンド目か。音の聞き分け・隠れ場所の選び方・囲い方・鬼が近いときの動き・追われたとき・鬼の特徴・お店の商品・宝石の道具・転生のタイミング。前と逆になったら「考えが変わった」）
- まとめ（3 つの性格を並べる）：遊んだ時間・ラウンド・逃げ切り・最高ステージ・転生の回数・隠れていた割合・お宝・不具合の数、グラフ（到達ステージの推移・得点の移動平均）
- **どこで詰まったか**：同じステージで 4 回以上見つかった所。挑戦・逃げ切り・続けて失敗・見つけた鬼・そのときの鬼の様子・拠点にいたか動いていたか
- **ステージごとの結果とクリアまでにかかった時間**（記録を始めてから初めて逃げ切るまで）・ステージ 25 を逃げ切ったか
- **転生**：いつ・どのステージで・何ポイント・その周の最高、周ごとの「各ステージに着くまでの時間」（転生後に速く進めるようになったか）

## バランスを推論する AI（`analyze.py`）

テストプレイ AI の記録を**全部**（4 つの性格・全部の記録のフォルダ）読み、ステージ・転生を重ねるとどうなるかを推論して、
**新しいファイル** `Saved/AgentPlaytest/analysis/balance_<日時>.md`・`.html`（最新は `latest.md`）を作る。Claude のトークンは使わない（手元の Python・標準ライブラリだけ）。

- 起動スクリプトが **1 時間ごとと 8 時間の終わり**に作り、GitHub の `agent-reports` の `<PC の名前>/balance.md`（最新）と `<PC の名前>/analysis/balance_<日時>.md`（作ったもの全部）に送る
- 手で作るとき：`python Tools/AgentPlaytest/analyze.py`
- 書くこと：推論のまとめ（難しくなる速さ・クリア率 50% を切るステージ・転生 1 回が何ステージぶんか・ステージ 15 / 20 / 25 / 30 に要る転生の回数・急に難しい／簡単なステージ・性格の差・稼ぎの伸び・壁を置かない割合と囲い方のクリア率・お宝の取りやすさ・宝石の道具）、
  Level カーブ（クリア率 = σ(a + b・ステージ + c・転生 + 性格) のロジスティック回帰と、ステージ 30・転生 10 回までの推論表）、ステージごとの特徴と傾向（挑戦・クリア率・難しさ・傾きとの差・隠れていた割合・追われた・壊された壁・稼ぎ・お宝・出てきた鬼・よく見つけた鬼・性格ごと）、
  転生による強化幅（同じステージで転生の回数が 1 違うときの差・周ごとの進み方）、置いた物とクリア率、鬼の種類ごと
- 遊ぶ AI と違い、作る人のための分析なので記録用の本当の値（TEL）も使う。ゲームの仕様（CSV）は読まない
- 先のステージに着くのは強くなった後なので、ステージの傾きは甘く出やすい（数字は目安）

## 気を付けること

- **Claude のセッションから起動するときは `explorer.exe` 経由で**（`Start-Process explorer.exe Tools\AgentPlaytest.bat`）。Claude のアプリが自動で更新・再起動すると、アプリの中から起動したゲームと AI も一緒に止まる（2026-10-16 03:10 に 5 つとも止まった）。ダブルクリックで起動したときは関係ない

- 3 つ同時に動かすと CPU・GPU を使う（既定は軽くして動かす）。それでも重いときは `-Personas near` のように減らす
- 速さ 2 倍だと、物理の 1 コマが大きくなるので、ごくまれに等倍では起きない引っかかりが出るかもしれない（不具合の報告は `-Speed 1` で確かめる）
- AI は人より下手な所がある（逃げ方は単純・道具の使い方は見当で決める）。数字は目安
